# meridian-ux.github.io

The marketing / main site for **meridian-ux** — *the declarative, cross-modal
console UI framework*. One descriptor proto (a form, a table, a command palette,
a conversation) renders natively in the browser, in a SwiftUI app, in the
terminal, and in wasm — re-skinned per tenant via `meridian.theme.v1`.

Astro (static), built hermetically on **Bazel 9** via
[`tomato-bazel/rules_astro`](https://github.com/tomato-bazel/rules_astro) — the
**same framework as `fastverk/site` and `tomato-bazel/site`**, re-skinned to the
meridian identity (cool azure → violet; the refracted-light **M** mark from
[`meridian-ux/brand`](https://github.com/meridian-ux/brand)).

🌐 **Live on GitHub Pages:** https://meridian-ux.github.io

## Feature-as-code

Each renderer owns its marketing metadata as a `fastverk.site.v1.Feature`
(`proto/fastverk/site/v1/feature.proto` — the schema is shared across the site
family). Seed protos live under `features/*.textproto`; the collector aggregates
them:

```
features/*.textproto  ──tools/collect_features.py──▶  src/content/features.json
                                                          │
                     /features (index of all)  ◀──────────┤
                     /features/<slug> (one page each: own hero + full <head>)
```

## Develop

```bash
pnpm install
# regenerate the catalog (needs protobuf on the interpreter):
FEATURE_PB2_DIR="$PWD/tools/gen/fastverk/site/v1" python3 tools/collect_features.py
pnpm dev           # local preview at /
pnpm build         # -> dist/
bazel build //:build   # hermetic build via rules_astro (Bazel 9)
```

## Manifest-generated conformance

`node tools/sync_conformance.mjs` resolves the public `meridian-ux/meridian`
main branch to an immutable SHA and imports its canonical
`schemas/conformance/coverage.json` into `src/content/coverage.json`, alongside
generated source provenance. Every deploy refreshes this snapshot before the
offline Astro build. Import failure stops the build; it does not silently publish
stale fallback data. The checked-in snapshot keeps local and Bazel builds
reproducible without network access during rendering.

`/conformance` derives every panel, conversation, and launchpad cell directly
from that manifest. It exposes reasons and waivers and distinguishes unverified
previews from declared rendering. The site smoke test verifies every emitted
cell and its exact status. For a verified local checkout, import offline with:

```bash
node tools/sync_conformance.mjs --manifest /path/to/meridian/schemas/conformance/coverage.json --revision FULL_COMMIT_SHA
node --test tools/sync_conformance.test.mjs
pnpm build
node tools/smoke_test.mjs
```

PR validation builds and tests without deploying. The existing main-branch
workflow still deploys GitHub Pages; merging a site PR therefore needs deployment
authorization in addition to normal review/CI approval.

## Deploy — GitHub Pages

Served as the **organization site** at `https://meridian-ux.github.io`. That only
works because the repo is named `<org>.github.io` — under any other name GitHub
Pages serves a *project* site at `/<repo>/` and the bare domain 404s, which is
exactly what it did until 2026-07-27. There is therefore **no `base`**, and links
and assets are plain absolute paths.

Every push to `main` runs [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml)
(`withastro/action` → `actions/deploy-pages`); enable Pages with **Source =
GitHub Actions**. The workflow deliberately passes no `package-manager:` input —
`package.json` `packageManager` is the single pnpm declaration, and supplying both
makes `pnpm/action-setup` hard-error on the duplicate.

For a custom domain, set `site: "https://<domain>"` in `astro.config.mjs` and add
a `public/CNAME`. If you ever reintroduce a `base`, note that
`src/styles/global.css` references fonts by absolute `url()` and cannot read
`import.meta.env.BASE_URL` — the prefix has to be threaded through the CSS by
hand, which is why the old `/site` prefix was hardcoded in 28 places.
